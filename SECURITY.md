# Безопасность и приватность данных

Заметки психолога о клиентах — это **особая категория персональных данных
(здоровье)**. В России их обработку регулирует 152-ФЗ; если среди клиентов есть
резиденты ЕС — ещё и GDPR. Это налагает требования, которые стартовый прототип
выполняет лишь частично. Ниже — что уже сделано и что обязательно доделать до
реального использования с живыми людьми.

## Что уже правильно
- **API-ключ ИИ не хранится в телефоне.** Приложение обращается к своему бэкенду
  (`backend/server.js`), а тот подставляет ключ из `.env`. Ключ не утекает к пользователю.

## Что ОБЯЗАТЕЛЬНО доделать (до работы с реальными клиентами)
1. **Вход по PIN/биометрии.** Никто, взявший телефон, не должен видеть заметки.
   → expo-local-authentication + блокировка приложения.
2. **Шифрование данных на устройстве.** Сейчас `store.js` использует AsyncStorage —
   это НЕ шифрование. → ключ шифрования в expo-secure-store (Keychain/Keystore),
   данные — в шифрованной БД (SQLCipher / op-sqlite).
3. **Серверное хранение с аутентификацией.** Если данные должны переживать смену
   телефона — бэкенд с БД, авторизацией пользователя и шифрованием в покое.
4. **Согласие клиента.** Экран/документ информированного согласия на ведение
   записей и на обработку их ИИ-ассистентом; возможность отказаться от ИИ.
5. **Минимизация данных, отправляемых в ИИ.** Продумать, какие поля реально нужны
   ассистенту; по возможности — псевдонимизация (имя → инициалы/ID).
6. **Право на удаление.** Полное удаление клиента и всех его данных по запросу.

## Важно понимать
Стартовый проект — это каркас для разработки, **не** готовое к продакшену
медицинское приложение. Пункты выше — не формальность, а условие законной и
этичной работы с данными о психическом здоровье. Обсудите их с Claude Code
(файл CLAUDE.md, приоритет №1) прежде, чем заносить настоящих клиентов.
