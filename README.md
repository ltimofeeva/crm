# Практика — CRM для психолога (мобильное приложение)

Мобильное приложение на Expo (React Native) с ИИ-ассистентом (Claude) и
подпиской через App Store / Google Play (RevenueCat).

> ⚠️ Перед работой с настоящими клиентами прочитайте `SECURITY.md`.
> Данные о психическом здоровье требуют шифрования, входа по PIN и согласия
> клиента — это ещё предстоит доделать (см. `CLAUDE.md`, приоритет №1).

---

## Что внутри
- **5 вкладок**: Сегодня, Клиенты (список + карта клиента с историей сессий),
  Контент, Аналитика (графики + воронка), Финансы.
- **ИИ-ассистент** (кнопки «Разбор ИИ», «Анализ ИИ» и т.д.). Работает через
  безопасный бэкенд-прокси (`backend/`) — ключ Claude API никогда не попадает в телефон.
- **Подписка «Практика Про»**: все ИИ-функции закрыты платной подпиской через
  RevenueCat (App Store / Google Play). Пока ключи RevenueCat не заданы —
  приложение работает в режиме разработки и ничего не блокирует.
- **Локальное хранение** клиентов и заметок.

Дальше — четыре части: **A** запуск для разработки, **B** ИИ (бэкенд) в
интернете, **C** подписка, **D** сборка приложений для Android и iOS.

## Часть A. Запуск для разработки (на своём телефоне)

Понадобится один раз:
1. **Node.js** 18+ — https://nodejs.org (кнопка LTS).
2. Приложение **Expo Go** на телефон (App Store / Google Play).
3. **Ключ Claude API** — https://console.anthropic.com → API Keys (`sk-ant-...`).

Шаги:
```
# 1) бэкенд (сервер для ИИ)
cd backend
npm install
cp .env.example .env        # впишите в .env свой ключ ANTHROPIC_API_KEY
npm start                   # оставьте окно открытым

# 2) приложение (в новом окне терминала, из корня проекта)
npm install
npx expo start
```
Телефон и компьютер должны быть в одной Wi-Fi сети. В `app.json` →
`extra.backendUrl` замените `localhost` на IP компьютера
(Mac: Системные настройки → Wi-Fi → Подробности; Windows: `ipconfig`),
например `"http://192.168.1.50:8787"`. Затем отсканируйте QR-код из
терминала в Expo Go.

Проверка ИИ: вкладка «Аналитика» → «Разбор ИИ». Если ответа нет — почти
всегда неверный адрес бэкенда или бэкенд не запущен.

## Часть B. ИИ в продакшене: выложить бэкенд в интернет

Для собранного приложения `http://192.168.x.x` не подойдёт — бэкенд должен
жить на сервере с постоянным адресом. Самый простой вариант — Render.com
(есть бесплатный тариф):

1. Загрузите проект на GitHub (если ещё не там).
2. На https://render.com → **New → Web Service** → подключите репозиторий.
3. Настройки: **Root Directory** = `backend`, **Build Command** = `npm install`,
   **Start Command** = `npm start`.
4. В разделе **Environment** добавьте переменную `ANTHROPIC_API_KEY` со своим
   ключом (и при желании `CLAUDE_MODEL`, по умолчанию `claude-opus-4-8`;
   дешевле — `claude-sonnet-5`).
5. После деплоя получите адрес вида `https://psy-crm-backend.onrender.com`.
   Проверьте в браузере: `https://ваш-адрес/health` → должно показать `{"ok":true,...}`.
6. Впишите этот адрес в `app.json` → `extra.backendUrl` (без порта, с `https://`).

> На бесплатном тарифе Render сервер «засыпает» после простоя, и первый ответ
> может занять ~30–60 секунд. Для реальных пользователей возьмите платный
> тариф (~$7/мес) — он не засыпает.

## Часть C. Подписка (оплата через App Store / Google Play)

По правилам Apple и Google цифровые подписки внутри приложения можно продавать
**только** через встроенные покупки магазинов. Мы используем **RevenueCat** —
бесплатный сервис-прослойку (до $2500 дохода в месяц), который сильно упрощает
работу с покупками на обеих платформах.

Что уже сделано в коде:
- Все ИИ-функции проверяют подписку (право/entitlement с именем `pro`).
- Экран подписки (`src/screens/PaywallScreen.js`) сам показывает цены и пакеты
  из RevenueCat, проводит покупку и восстановление покупок.
- Пока ключи RevenueCat пустые — всё открыто (режим разработки).

Что нужно настроить (по порядку):

1. **Аккаунты разработчика** (нужны в любом случае для публикации):
   - Apple Developer Program — $99/год, https://developer.apple.com
   - Google Play Console — $25 однократно, https://play.google.com/console

2. **Создать подписку в магазинах**:
   - App Store Connect → ваше приложение → **Подписки** → создать группу и
     подписку, например `praktika_pro_monthly` (месяц) и `praktika_pro_yearly` (год).
   - Google Play Console → приложение → **Продукты → Подписки** → те же товары.

3. **RevenueCat** (https://www.revenuecat.com, регистрация бесплатна):
   - Создайте проект, добавьте два приложения: iOS (bundle id
     `com.ltimofeeva.praktika`) и Android (тот же package name).
   - **Entitlements** → создайте право с идентификатором `pro`.
   - **Products** → подтяните товары из магазинов и привяжите их к праву `pro`.
   - **Offerings** → создайте offering `default` и добавьте в него пакеты
     (Monthly / Annual) — именно их покажет экран подписки.
   - Скопируйте **публичные API-ключи** (Project Settings → API Keys):
     ключ `appl_...` для iOS и `goog_...` для Android.

4. **Впишите ключи в `app.json`**:
   ```json
   "extra": {
     "backendUrl": "https://ваш-бэкенд.onrender.com",
     "revenueCatIosKey": "appl_ВАШ_КЛЮЧ",
     "revenueCatAndroidKey": "goog_ВАШ_КЛЮЧ",
     "revenueCatEntitlement": "pro"
   }
   ```

> Важно: покупки НЕ работают в Expo Go — только в собранном приложении
> (часть D). Тестовые покупки: на iOS через Sandbox-аккаунт (TestFlight),
> на Android через список тестировщиков в Play Console.

## Часть D. Сборка приложения для Android и iOS (EAS Build)

Сборка делается в облаке Expo — свой Mac не нужен даже для iOS.

1. Аккаунт на https://expo.dev (бесплатно) и установка утилиты:
   ```
   npm install -g eas-cli
   eas login
   ```
2. Привязать проект (один раз, из корня проекта):
   ```
   eas init
   ```
3. **Android — тестовый APK** (можно поставить на свой телефон напрямую):
   ```
   eas build --platform android --profile preview
   ```
   По окончании появится ссылка на скачивание `.apk` — откройте её на телефоне
   и установите.
4. **Android — публикация в Google Play**:
   ```
   eas build --platform android --profile production
   eas submit --platform android
   ```
5. **iOS** (нужен аккаунт Apple Developer, $99/год):
   ```
   eas build --platform ios --profile production
   eas submit --platform ios
   ```
   EAS сам создаст сертификаты. Дальше — TestFlight для тестов и отправка
   на проверку в App Store.

> Идентификаторы приложения (`com.ltimofeeva.praktika`) заданы в `app.json`.
> Их можно поменять на свои, но ДО первой публикации — после публикации
> поменять нельзя.

> Для отладки покупок удобен профиль `development`
> (`eas build --profile development --platform android`) — это специальная
> сборка (dev client), в которой работают и покупки, и горячая перезагрузка кода.

## Частые проблемы
- **Пустой экран / ошибка Metro**: остановите (`Ctrl+C`) и снова `npx expo start -c`.
- **ИИ не отвечает**: бэкенд запущен? адрес в `app.json` верный? В собранном
  приложении адрес должен быть `https://...` (часть B), не локальный IP.
- **«Network request failed»**: то же самое — проверьте адрес и что сервер работает.
- **Экран подписки пустой в собранном приложении**: проверьте, что в RevenueCat
  создан offering `default` с пакетами и что ключи в `app.json` — публичные
  (начинаются с `appl_` / `goog_`).
- **Покупки не работают**: в Expo Go они и не должны — соберите dev client или
  APK (часть D).
